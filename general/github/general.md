# GitHub Practices

General guidelines for how we work with GitHub throughout the club, branch and commit naming, opening and reviewing pull requests, repository structure, and cleaning up commit history with rebasing. If you're contributing code to the club, try to follow as many of these as you reasonably can.

:::tip
New to the club or to Git in general? Start with [Pull Requests & Collaboration](./pull-requests) — it covers the day-to-day workflow you'll use most often.
:::

## What's covered

- **[Pull Requests & Collaboration](../pull-requests)** — working in parallel on the same branch, and how we open and review PRs.
- **[Development Practices](../development-practices)** — branch naming and commit message conventions.
- **[Repository Practices](../repo-practices)** — repo naming, and what makes a repo pleasant to develop in.
- **[Commit Rebasing](../rebasing)** — cleaning up commit history with interactive rebase.
